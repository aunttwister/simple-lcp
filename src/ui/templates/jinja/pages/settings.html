Conversation titling

After each served request LCP can ask the gateway's own chain head to write a short title and summary for the conversation, in the background. Titles make the Conversations history searchable by what it was about instead of "Untitled". Titling never runs on the request path and never fails a request.

Model intelligence

LCP learns which models exist and how they score from outside sources. Nothing is fetched until you switch it on here, and each source is accepted separately — a source you do not trust is simply never read. Discovery never changes routing: a model the poller finds is staged for review, and an observed name that maps to no known model goes to the identity queue instead of being stored as if it were known.

Guard: a listing under 50% of the known active set is treated as a truncated read, not a mass retirement — nothing is staged from it. Minimum 300s between polls.

Identity queue

Names observed from a source that map to no known model. They are not stored as capability data — a row keyed by a spelling no lookup searches can never be joined, and it makes coverage look better than it is. Accepting one writes the alias that makes the link real and re-keys any capability rows stored under it. A suggested model is an unverified guess: confirm the generation before accepting.
