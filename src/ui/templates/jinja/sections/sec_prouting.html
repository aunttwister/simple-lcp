Intent margin gate stop reordering on a near-tie {% if routing.intent_margin_gate %}{{ routing.intent_margin_gate }}{% else %}off{% endif %}

This one is a {{ profile.name }} setting, not a router setting — the router reads it from the profile's config, so it saves to the profile, not to /api/routing/policy. When dynamic routing would reorder the chain and the classifier's top two intents score closer together than this margin, there is no decision to make and the chain keeps its declared order. 0 = off, and off is what an unset field means.

Measured 2026-09-26 — do not switch this on in production as it stands. Leaving it off changes nothing. Over a 14-day window, 97% of the reorders the gate would block are pure provider swaps for the same logical model — a choice the intent margin carries no information about, because it is decided by provider ranking (breaker state, balance, cost, chain order). A 0.02 gate would have kept ~6,835 requests on the dearer lane: ~$150 forgone per 14 days (~$390/month) and ~10.3 hours of extra wall-clock wait on {{ profile.name }}. The gate is the right idea aimed one layer too low: it should veto changing the model, not choosing a cheaper provider. See PLAN §26; the re-aim is M4.
