A header row is required and column order is free. Aliases are accepted for the first three (model_slug, task/axis, value). score takes 0–1 or 0–100 and is normalised. An unknown task_type is an error, not a skipped row — the router reads the eight routing axes and nothing else, so a typo would create a score nothing consults. A file with any error writes nothing; fix the file and re-import. Imported rows are tagged import, so they never overwrite benchmark or hand-entered scores, and those never overwrite them.

Poll latest data

Reads LiveBench's own published files — the release table and the suite definitions that sit beside it — and writes the six axes it can measure. Nothing is scraped and no site is rendered: those two files are what livebench.ai itself displays. LiveBench is the only benchmark this matrix is polled from.

What a poll does — and does not — touch
a score that came from after a poll
manual typed here, or Edit still served. A hand-entered score outranks a polled one, so a poll can never overwrite a number you set.
import a CSV you loaded untouched, but it does not grade. A file that names no source is tagged import, which is stored and never served — name manual or livebench in the file to have it count.
livebench a previous poll replaced by the newer value — that is the point of polling.
lmarena the arena boards untouched, and never served. An arena percentile is a rank within a field, not a measurement, so it is stored and queryable but does not grade.
If LiveBench has no row for a model
The poll writes only a model it can resolve to a registry entry, through the slug, the benchmark key, an alias or a served id. Names it cannot resolve are queued for review instead of being written against a spelling nothing reads — the count is in the result. LiveBench names models by version and effort setting (…-max-effort), so a model whose registry key lacks that suffix is queued rather than silently mismatched.
