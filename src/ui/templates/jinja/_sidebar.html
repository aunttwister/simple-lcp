{# M2b — flat navigation. No group labels: every entry is a page, and the two groups ("Work" / "Gateway") only made the reader classify before clicking. Profiles — the directory: one card per routing subject, and each card opens that profile's routing rules, its model pool and the API keys that call it. First, because the profile is the unit every other page is scoped to. Models — the capability matrix + where those models come from Activity — what happened: the cost/token overview and every log realm. Before Conversations, because the log is the surface you open to answer "what did the router do", and conversations are the drill-down from a row in it. Conversations — what is happening NOW and everything that has happened. The live half is the in-process registry: the Requests log gains a row only when a call completes, so a running call appears nowhere else. The history half is LCP's own conversation store. One page, because "the call I am waiting on" and "the calls that preceded it" are the same question asked at two times. Usage — spend per provider, balances, and the scrape cache (its own page: it is a billing view, not a log) Alerts — things to act on (R10: alerts and budgets are per subject) Settings — estate-level switches with no per-provider home (first tenant: CUR-329 conversation titling). Last: you come here to change behaviour, not to see it. Setup, Tasks and Fleet are not here: they were the work module's own pages, and the module's remaining surface is a Hermes concern. Skills, memory and cron left the profile page for the same reason on 2026-10-24, and Config — the work-layer paths editor — followed on 2026-10-25. The provider-credit submenu and the usage-cache refresh button lived on the Activity entry; both are gone. Usage carries its own refresh controls, so no capability is lost — only the duplicate shortcut. #}
