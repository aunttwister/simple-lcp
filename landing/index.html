A control plane for LLM traffic

Every LLM call your agents make, routed, metered and accounted.

LCP sits between your agents and their providers. Each profile carries its own provider chain, tool policy and budget. One container, one port, SQLite. No Postgres, no Redis, no cloud.

Clone the repo AGPL-3.0 · runs on hardware you own

You cannot control what you cannot see. LCP makes every call visible before it becomes a bill.

Three problems, one container

LCP was built for a homelab running six agent profiles against five providers. Each problem below is the reason a piece of it exists.

Spend was a black box

Agents hit providers directly. Nobody knew what was spent, by whom, or on what task type. Now every request writes a row: provider, model, tokens, cache hits, latency, cost.

Tool policy was unenforceable

A coding agent could call cronjob or write_file against production and nothing in the loop could stop it. Now tool allow lists are applied per profile, on the request path, failing closed.

Failures were manual

A dead provider meant hand editing per profile configs and hoping nobody noticed. Now a persisted circuit breaker trips the provider and the chain moves on.

How it works

Three steps. No SDK, no client changes, no second service to run.

01

Point the client at a profile

Any OpenAI client calls POST /<profile>/v1/chat/completions. VS Code Copilot, curl and agent harnesses all work unchanged.

02

The chain decides

Static fallback order or dynamic routing: the request is classified, then the pool is ranked by capability score, cost bias and breaker health.

03

The ledger records it

One SQLite row per request, plus /metrics for Prometheus and a dashboard for the human.

What is in the box

Every item below ships in the single container. Nothing is a paid tier.

Budgets that stop the call

A key, a profile or a provider can carry a spend limit. On breach the request returns 403 before the provider is contacted.

Circuit breaker, persisted

Failures are counted per provider and the tripped state survives a restart, so a flapping provider stays out of the chain.

Semantic routing

Requests are classified against per profile intents, then ranked by benchmark score, cost bias and health. A margin gate stops coin flip decisions.

Tool permissions

Each profile gets an allow list of tools, with a global block layer on top. A new tool is blocked until you whitelist it.

Speaks the OpenAI API

Chat completions, model listing and streaming on the paths your clients already call. Local vLLM and llama.cpp are just more providers.

No external services

SQLite for state, Python for the server, one port. No Postgres, no Redis, no message broker, no build step in the dashboard.

Questions worth asking

Is this a hosted service?

No. LCP is a container you run yourself, backed by SQLite. There is no account, no telemetry and no control plane outside your network.

Do my clients need to change?

No. The endpoints follow the OpenAI shape, so an existing client only needs its base URL pointed at http://<host>:8734/<profile>.

Does it replace Postgres or Redis?

Yes. State lives in one SQLite file. That is a deliberate constraint: it keeps the install to one container and one port.

Can it serve local models?

Yes. A vLLM or llama.cpp endpoint is registered as a provider like any other, so a local model sits in the same chain and writes the same cost row. Local models usually cost $0, which is itself useful data.

What happens when a budget is exceeded?

The request returns 403 and the provider is never called. The breach is also recorded as an alert, so you see which key or profile hit the wall.

How is cost calculated?

From the provider's pricing entry and its cost plugin, applied to the prompt and completion tokens of the response. Every response carries X-Estimated-Cost.

Is it safe to expose to the internet?

Not as shipped. LCP expects a LAN or VPN boundary, with TLS terminated by a reverse proxy in front of it. It is explicitly not designed to isolate untrusted tenants.

What licence is it under?

AGPL-3.0. The source is at github.com/aunttwister/lcp.
